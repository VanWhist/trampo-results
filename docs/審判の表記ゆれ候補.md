# 審判の表記ゆれ候補（同一人物が2つのIDに分かれている可能性）

> **2026-08-14：下の5組はVanさんの確認を受けて `etl/judge_overrides.json` に反映済みです。**
> 統合後、既定の母集団で n≥100 の審判が24名→**22名**、完遂のみで52名→**50名**になり、
> 実装指示書7-2の記載（22人・完遂のみ50人）と一致しました。
> AIDA Yasushi のみ国内側に該当者がおらず未統合です（統合不要）。
>
> 選手側の同じ問題は `docs/選手の表記ゆれ候補.md`（ETLが毎回自動生成）にあります。

## 何が起きているか

sporttech は、**国内大会では日本語表記、国際大会ではローマ字表記**で審判名を持っています。
両方で審判をしている人は、氏名を鍵にしている以上、別々のIDになります。

| | 審判の数 |
|---|---|
| 日本語表記（国内大会のみに出現） | 62名 |
| ローマ字表記（国際大会のみに出現） | 112名 |

読みを機械的に当てにいくと別人を混ぜる危険があるので、自動では結合していません。

## 統合するときの書き方

`etl/judge_overrides.json` の `merge` に足してください。`judge_id` は自由に付けられます。

```json
{
  "merge": [
    { "judge_id": "j-sakuma-hiroshi",    "names": ["佐久間 洋", "SAKUMA Hiroshi"] },
    { "judge_id": "j-yamamoto-norifumi", "names": ["山本 宜史", "YAMAMOTO Norifumi"] },
    { "judge_id": "j-okajima-masaharu",  "names": ["岡嶋 正治", "OKAJIMA Masaharu"] },
    { "judge_id": "j-muto-shinya",       "names": ["武藤 真也", "MUTO Shinya"] },
    { "judge_id": "j-ikeda-nariaki",     "names": ["池田 成諒", "IKEDA Nariaki"] }
  ]
}
```

そのあと再生成します。

```bash
python -m etl.build
```

## 統合すると数字が変わります

いま「完遂のみ」の母集団で、分かれたまま集計されている例です。

| 審判 | n | 平均パネル差 |
|---|---|---|
| 山本 宜史 | 602 | +0.087 |
| YAMAMOTO Norifumi | 168 | −0.043 |
| 岡嶋 正治 | 277 | −0.051 |
| OKAJIMA Masaharu | 156 | −0.071 |

山本さんは国内と国際で符号が逆に出ています。統合すると平均は中間に寄ります。
**どちらが正しいかは統合してみないと分かりません**が、分かれたままだと
「同じ人の国内での傾向」と「国際での傾向」を別人として並べていることになります。

なお、この分かれ方は既定の母集団（予選通過者×完遂）の「辛め」判定にも効きます。
池田 成諒は現在 n=128・平均差 −0.413 で最も辛い側ですが、IKEDA Nariaki の n=15 は
別に数えられています。

## 統合しない場合

そのままでも画面は動きます。ジャッジ分析の画面に、国内・国際で表記が違うため
同じ審判が2回並ぶことがある旨を注記してあります。
