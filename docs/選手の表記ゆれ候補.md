# 選手の表記ゆれ候補（同一人物が2つのIDに分かれている可能性）

**このファイルは `python -m etl.build` が毎回作り直します。手で編集しても上書きされます。**

**Vanさんの確認をお願いしたい件です。** 確認できたら `etl/athlete_overrides.json` の
`merge` に書き足して `python -m etl.build` を回すと統合されます。こちらで勝手には結合していません。

## 何が起きているか

sporttech は、**国内大会では日本語表記、国際大会ではローマ字表記**で選手名を持っています。
氏名を鍵にしている以上、両方に出ている選手は別々のIDになります。

**影響が大きいのは、抜けるのがW杯・アジア選手権に出るトップ層**だという点です。
選手ページを開くと、国際大会の記録だけが載っていない状態になります。

| | |
|---|---|
| 統合の候補（未処理） | 72名 |
| うち日本語表記側の候補が1人に絞れたもの | 37名 |
| 候補が複数あり要確認 | 1名 |
| 生年月日が「年だけ」で絞れないもの | 34名 |
| すでに overrides で統合済み | 79名 |

## 候補の絞り方

1. 所属が `JPN` で氏名がASCIIのみ（＝国際大会側のレコード）
2. 日本語表記側と **出場大会の日付が一切重ならない**（同じ日に別々に出ていたら別人）
3. 男女が食い違わない
4. 生年月日が一致する。ただし **`YYYY-01-01` は「生年しか分かっていない」**ものとして
   日付の一致判定には使わない（そういうレコードが188件あります）
5. 生年しか分からない場合は、**すでに承認済みの統合から覚えた「ローマ字の姓→漢字の姓」**を
   使い、同姓・同生年の選手が1人だけならその人を候補にする
6. それでも決まらない場合は**種目**で絞る。タンブリングの選手が国内で個人に出ることは
   まずないので、同じ種目・同じ生年で1人だけなら強い手掛かりになる

**種目では絞っていません。** 個人だけを見ると、DMT・タンブリング・シンクロで
国際大会に出ている選手（分裂しているのはまさにこの層）を丸ごと取りこぼします。

生年月日は**候補を絞る手掛かりとしてだけ**使っています。統合の鍵にはしていません
（大会によってブレるためです）。読みの一致だけで自動採用はしていません。
