# 西日本 第51回（2023）予選PDFの書き起こし

`51th_WestJapanTRA_Qualification_results.pdf`（50ページ、sporttech の採点システムの出力）は、
文字がすべて図形の輪郭（ベクター）になっていて、文字として取り出せない。ここにあるのは、
それを書き起こして `etl/nishinihon_51q_transcription.csv` を作ったときの一回限りの手順と、
人が目で見て決めた内容の記録。ETL はこの CSV を読む（PDF の SHA-256 が変わっていたら止まる）。

## 手順

1. `glyph51.py` … 輪郭を、表の横罫線で選手ごとの帯 → 上下2行 → 字 → 語に分ける。
   列名の行（S1〜Score）の位置で、数値の語を列に割り当てる。表の最後の行の下には罫線が無いので、
   最後の罫線の下に字があれば帯を1つ足す（選手が1人だけのページは罫線が列名の下の1本だけ）。
2. `digits51.py` … 数値の列の字（約3.2万字）を、形の重なり（IoU ≥ 0.8）で 52 種類にまとめ、
   見本を `digit_shapes.png` に並べる。
3. `parse51q.py` … 見本ごとに人が見て決めた文字（`LABELS`。0〜9・小数点・DNS の D/N/S）で
   全セルを読む。見本に合わない字は 0。
4. `check51q.py` … 検算。全演技で次の3式を満たすこと：
   - E = 2 × 跳んだ技の数 − (S の合計 + L) ÷ 10
   - E + D + H + Time = Total
   - 1本目の Total + 2本目の Total = Score（予選の値）
   合計欄が PDF で「…」と印字されている3件は、E+D+H+T と「予選の値 − もう1本」の両方で確かめた値を使う。
5. `fields51q.py` → `winocr.ps1` … 氏名欄・所属欄・1行全体を切り出し、Windows 標準の文字読み取り
   （Windows.Media.Ocr、日本語）にかける。
6. `match51q.py` … 読んだ氏名を既存の選手名と突き合わせる。1行全体の読み取りが既存の選手名と
   1字も違わずに一致したものだけ自動で採用し、所属はその選手の既存の所属から選ぶ。
7. `sheet51.py` … それ以外（1字違い・候補なし・同じ所属に1字違いの別選手がいるもの）を一覧画像にし、
   人が画像を見て氏名・所属を決めた。結果が `visual_names.tsv`（214名）と `visual_clubs.tsv`（22件）。
   （各スクリプトは作業フォルダに置いたこの2つのファイルを読む）
   自動で選んだ所属のうち、文字読み取りと完全には一致しないもの（70件）も画像で確かめた
   （「TEN（テン）トランポリンクラブ」を既存の「TEN トランポリンクラブ」にしていた1件を直した。
   「forte TC」はこのPDFでは空白なしの「forteTC」と印字されているので、そろえた）。
   目視の誤りが2件あり、直した：
   - 若杉 昴 を「昂」と読んだ（第51回決勝の名簿との照合で発見）
   - 大石 凜羽 を「凛羽」と読んだ（凛と凜は見分けにくいので、名前に凛・凜を含む8名を、
     第51回決勝で字の対応表から確定している「椿原 凜太郎」「門前 凛香」の字の形と輪郭の重なりで比べた）
   レビューでさらに見つかって直したもの：
   - 22ページ（選手1人だけのページ）の棄権 末松 蒼麻 が抜けていた
   - 山﨑 真衣・川﨑 晴斗 の﨑を崎と書いていた（公開時は既存の決まりで崎にそろう）
   - 「神辺スポーツセンター」を欄で切れて印字と記録していたが、実際は最後の「ー」まで印字されていた
   検算用に `namecheck51q.py`・`relcheck51q.py`（読んだ氏名と、取り違えやすい字に置き換えた候補を
   メイリオで描いて PDF の図形と重ねる）も置いたが、名前全体の重なりは字の太さ等でばらつくので
   目安にとどまる（差の出た10件は拡大して目で確かめ、すべて読みどおりだった）。
   なお、このPDFの書体はメイリオ（「齊藤 結夢」の齊を、メイリオの齊・齋・斉・斎と重ねて確定）。
8. `assemble51q.py` → `final51q.py` … 区分（見出し）・順位・氏名・所属・値を組み立てて CSV に書き出す。
   予選の上位10名が第51回決勝の名簿（`nw-2023-09-29` の決勝）と全区分で一致することを確かめた。

## CSV の列

`category, rank, name, club, dns, routine, S1..S10, L, E, D, H, Time, Total, Score, page, how, note`

- `how`：`ocr+db`＝文字読み取りが既存の選手名と完全一致、`visual`＝人が画像を見て決めた
- `dns=1` の行は棄権（値なし）。1本目を演技していない選手（合計 0）は、その本目の行が無い
- `note`：合計が「…」で印字されている、など
