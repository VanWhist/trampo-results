# 東日本 画像のPDF（文字が図形）の書き起こし

2023年の第47回東日本選手権（予選6区分）・第31回イーストジャパン（学年別5区分）と、2024年の第48回東日本選手権
（全8ファイル）の結果PDFは「Microsoft Print To PDF」で出力されていて、文字がすべて図形の輪郭になっている
（文字として取り出せない。列名の行だけは小さな画像）。ここにあるのは、それを書き起こして
`etl/higashinihon_img_transcription.csv` を作ったときの一回限りの手順と、人が目で見て決めた内容の記録。
ETL（`etl/sources/higashinihon_pdf.py`）はこの CSV を読む（PDF の SHA-256 が `etl/higashinihon_files.json` の
`image_sha256` と違えば止まる）。各スクリプトは作業フォルダで実行し、途中のファイルもそこに書く。

## 手順

1. `lay.py` … 1ページ目の列名の行（小さな画像 21 語）から列の位置を決め、全ページに使う。部品（塗りつぶしの
   輪郭と、罫線でない小さな四角＝小数点・漢字の画の一部）を、横罫線で選手ごとの帯に分け、区域（順位・氏名と所属・
   予選の印・数値）→ 行 → 字に分ける。次の場合を扱う：
   - ページの最後の選手は下の罫線が無いことがある（最後の罫線より下も帯にする）
   - 選手の途中でページが変わると、次のページの最初の罫線より上に所属の続きが出る（前の帯に足す）
   - 最後のページの最後の罫線より下は表の外（2023年版の「produced by T-product 2023 Export CSV」）。
     右下の「©2023 T-product.All Rights Reserved.」は右寄せで表の右端より右まで出るので外す
2. `digits.py` … 順位と数値の列の字（約3.4万字）を、ファイルごとの列の間隔で大きさをそろえ、形の重なり
   （IoU ≥ 0.8）で 45 種類にまとめ、見本を `digit_shapes.png` に並べる。
3. `parse.py` … 見本ごとに人が見て決めた文字（`LABELS`。0〜9・小数点・DNS）で全セルを読む。予選の印（予選1・
   予選2）の行に上下の位置が最も近い数値の行を、その本目とする。氏名・所属の行は白い余白を付けて画像に切り出す。
4. `check.py` … 検算。全演技（896本）で次を満たすこと：
   - Exe = 2 × 跳んだ技の数 − (S の合計 ＋ L ＋ A) ÷ 10（L は10本跳び終えた演技だけ）
   - Score = Exe ＋ Diff ＋ ToF ＋ HD − Pen
   - 選手の値 = 2本の良いほう（Best）／合計（Total）。どちらかは列名の行の最後の語（画像）で見た（`meta.AGG`）
   - 順位は選手の値の大きい順（同点で順位が分かれるのは、規則による順位付け。例：跳躍時間の大きい方が上）
   `LABELS` の打ち間違い（2か所）はこの検算で見つかった。
5. Windows 標準の文字読み取り（`tools/transcribe_nishi51q/winocr.ps1`）で切り出した行を読む。
6. `textref.py` … 同じ大会の文字のPDF（2023東日本の決勝・2023イーストジャパンの他区分）を ETL の読み方で読み、
   氏名・所属の参照にする（`ejtext.json`）。
7. `match.py` … 読んだ氏名（空白・読み仮名を除く）が既存の選手名か参照の氏名と1字も違わなければ採用（how=ocr+db）。
   所属は既存の所属から編集距離が最小のものを候補にする。通し番号 `_i`（`decisions.tsv` の番号）を付け、
   目で確かめる行を `need.json` に書く。既存の選手名はこの取り込みより前の `data/athletes.json` を使った
   （取り込んだ後に実行し直すと、目で決めた氏名も自動で通ってしまう）。
8. `sheet.py need.json rv 22` … 氏名が決まらないもの・所属が読み取りと完全には一致しないもの・選手の既存の所属に無いもの（365名）を
   一覧画像にし、人が見て氏名・所属を決めた（`decisions.tsv`）。所属は印字どおりに書く（`[都道府県]` は外す）。
   取り違えやすい字（凛/凜・昂/昴・曽/曾・栞/琹・齊/齋/斉 など）を含む31名は拡大して確かめ、凛/凜の6名は
   `refglyph.py`（同じ書体 M PLUS 1p の文字のPDFにある実物の凛・凜と重ねる）でも比べた。既存の選手名
   （合寳 凛菜・唐澤 凛・山本 凛華・前野 凜太郎）と一致した。
   既存の所属から選んだ表記は、所属ごとに1つの画像で印字と比べ、違うものを直した（`assemble.CLUB_PRINTED`。
   例：2023年は「大館トランポリンクラブ」、2024年は「大館市トランポリンクラブ」と印字）。
9. `assemble.py` … CSV に書き出す（930行＝演技896本＋棄権・演技なし34名）。

確かめたこと：
- 2023東日本の予選の上位10名が、文字のPDFの決勝の名簿と全6区分で氏名・所属とも一致
- 2024東日本の予選の上位10名が、決勝（これも画像のPDF）の名簿と全4区分で一致

## CSV の列

`meet_id, file, page, category, sex, round, rank, name, club, status, routine, S1..S10, L, A, Exe, Diff, ToF, HD, Pen, Score, agg, agg_kind, how_name, how_club`

- `status`：`DNS`（Score 欄に DNS）・`演技なし`（値が 0.00 だけ）。演技の行は空
- `agg`：選手の値（`agg_kind` が Best なら良いほう、Total なら合計）
- `how_name`・`how_club`：`ocr+db`＝文字読み取りが既存の表記と完全一致、`visual`＝人が画像を見て決めた
