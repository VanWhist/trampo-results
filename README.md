# トランポリン大会リザルト（Phase 1）

トランポリン大会のリザルトを、選手名で引いて見るためのアプリです。
①リザルト一覧 ②選手ページ ③演技詳細 ④ジャッジ分析 の4つの画面があります。

**対象は個人種目だけ**です。シンクロ・DMT（ダブルミニ）・タンブリングのデータも
捨てずに持っていますが、画面には出していません（`data/performances/<年>-other.json` にあります）。

`<作業フォルダ>` で Claude Code を起動して、そのまま貼り付けてください。

置き場所は `<作業フォルダ>\トランポリンルール\大会リザルト\` の下です。

### ステップ3：この3行だけ見てください

**① `errors` が 0 か**

| | 意味 | どうするか |
|---|---|---|
| `errors: 0` | 問題なし | 次へ進む |
| `errors: 1以上` | **公開しない** | `docs/検証レポート_ETL.md` の「エラー」の節に、何がどう食い違ったかが1件ずつ書いてあります。Claude Code に見せて直してもらってください |

`warnings` は0でなくて構いません。**警告は「人が見て決めること」の置き場**です
（審判の表記ゆれ、新しく取り込んだ大会など）。中身は検証レポートに一覧があります。

**② 新しい大会が取り込まれたか**

新しい大会を足すと、警告にこう出ます。

```
2026-09-13 第54回西日本トランポリン競技選手権大会 を新しく取り込みました（個人 900件）。
内容を確認したら `python -m etl.build --accept-counts` で基準を更新してください
```

件数が想定どおりなら、画面で中身を確認してから基準を更新します。

```bash
python -m etl.build --accept-counts
```

これは「この件数を正しいものとして覚える」操作です。次回以降、**すでに取り込んだ大会の
件数が勝手に変わったらエラーになります**（取りこぼしや二重取り込みを見つけるため）。
覚えさせないと、次に回したときも同じ警告が出続けます。

**③ 受け入れ基準が通るか**

```bash
python -m etl.acceptance
```

7項目すべてに `OK` が付けば大丈夫です。項目1は「実装時より件数が減っていないこと」を見ます。
**減っていたら取りこぼし**なので、公開しないでください。

## 4. 数字の作り方（ここを崩さないでください）

正しさはすべて `etl/`（Python）に閉じ込めてあります。**アプリ側（`js/`）に条件分岐を持ち込まないでください。**
2つの画面で数字が食い違わないのは、これが理由です。

### 検算式

```
合計 = D + E + T + HD + Bonus − Penalty − DPenalty
N = 10 : E = 20  − (位置1〜10の減点 + 着地減点) / 10
N < 10 : E = 2N  − (位置1〜Nの減点) / 10          ← 着地減点は乗らない
```

満点は固定20点ではなく**実際に跳んだ技数に比例**します（§19.9）。
2017年版以降の規則の個人演技42,017件で成立しています（要確認1件）。

**2017年版より前の規則（2015〜2017年2月の大会）は式が違います。** 2015〜2026年の全大会で確かめました。

```
合計 = D + T + 3×E + Bonus − Penalty − DPenalty     ← HD は存在しない（4,533件で100%成立）
E    = N − (位置1〜Nの減点 + 着地減点) / 10         ← E は審判1人ぶんの尺度（10点満点）
```

旧規則の E の式は4,533件中86件で合いません。理由が分からないので規則にはせず、警告で件数を出しています。
大会ごとに規則の版（`rules`・`rules_family`）を持たせ、検算・集計・画面の注記をそれで切り替えています。
自己ベストは今の規則の演技だけで出します（旧規則の最高は別に表示）。

演技していない枠（棄権など）は、審判欄がすべて初期値（100）でD・T・合計が0なのに、
Eだけ満点が入っています。E は空欄にして検算から外しています（12件）。
説明のつかない1件は `etl/known_exceptions.json` に理由つきで登録しています。

**Eを式から導出していません。** 画面に出すEは各ソースの印字値で、式は許容幅つきの検算と
「要確認」フラグにだけ使っています。

### 減点には2つの単位があります。混ぜると約2倍ずれます

| 単位 | 該当データ | 値域 |
|---|---|---|
| `median2_sum_tenths`（中央2審判の和） | sporttech 全体／大阪府の**E行** | 技0〜10・着地0〜20 |
| `single_judge_tenths`（審判1人ぶん） | 大阪府の**E1〜E4行** | 技0〜5 |
| `pre2017_single_scale_tenths`（1人ぶんの尺度） | sporttech の**2017年版より前の規則**の大会 | 技0〜5程度 |

技位置別の平均（`summary/deductions.json`）は `median2_sum_tenths` だけで出しています。

`deduct_unit` 列を必ず持たせています。**列名と単位列の両方に単位を残す方針を崩さないでください。**

### 技位置別の集計はスロット1〜技数まで

中断した演技では跳んでいない位置に `0` が入り、さらに中断した技の減点が技数を超えた位置に
記録されることがあります。**ゼロ埋めを外すだけでは足りません。**
技数を超えた位置の値は `unaccounted`（未算入）に隔離し、演技詳細で件数を出しています。

### 選手の名寄せは氏名だけ

所属も生年月日も鍵にしていません。実データでの分裂率は
氏名のみ 0% ／ 氏名＋生年月日 6.7% ／ 氏名＋所属 10.7% でした。

- **所属は「属性」**です。演技ごとに持ち、選手ページで履歴表示します
  （城 瑛斗：2025 アベノジュニアトランポリンクラブ → 2026 阪南大学クラブ）
- **生年月日は大会によってブレます**（城 瑛斗は5大会で 2013-06-20、2026-07-24 だけ 2014-07-12）。
  保存はしていますが、鍵にも表示にも使っていません

### 日本語表記とローマ字表記の分裂に注意してください

sporttech は**国内大会を日本語表記、国際大会をローマ字表記**で持っています。
氏名を鍵にしている以上、両方に出る人は別々のIDになります。

**影響が大きいのは、抜けるのがW杯・アジア選手権に出るトップ層**だという点です。
選手ページを開くと、国際大会の記録だけが載っていない状態になります。

ETLが毎回候補を洗い出して警告に出し、一覧を作り直します。

| | 候補一覧 | 統合する場所 |
|---|---|---|
| 選手 | `docs/選手の表記ゆれ候補.md`（自動生成） | `etl/athlete_overrides.json` |
| 審判 | `docs/審判の表記ゆれ候補.md` | `etl/judge_overrides.json`（5組を統合済み） |

選手は27組、審判は5組を統合済みです（2026-08-14 時点）。

候補の絞り込みは「所属が JPN・氏名がASCIIのみ・出場日が一切重ならない・生年月日が一致」です。
**生年月日は候補を絞る手掛かりとしてだけ**使い、統合の鍵にはしていません。
読みの一致だけで自動採用することもしていません。**最後は人が決めてください。**

`docs/選手の表記ゆれ候補.md` には貼り付け用のJSONが入っています。

**同姓同名の別人が出てきたら** `etl/athlete_overrides.json` に手で1行足してください。
自動で賢く判定させないための仕組みです。現データでは同姓同名の別人は1件も見つかっていません。

```json
{
  "split": [ { "name": "山田 太郎", "groups": [
      { "athlete_id": "yamada-taro-1", "meets": ["2025-05-17"] },
      { "athlete_id": "yamada-taro-2", "meets": ["2026-07-24"] } ] } ],
  "merge": [ { "athlete_id": "shiro-eito", "names": ["城 瑛斗", "城　瑛斗"] } ]
}
```

## 5. ジャッジ分析について

指標は生の平均Eではなく**パネル内差**です。

```
審判差 = その審判のE − 同じ演技のパネル中央値
```

生の平均Eを使うと「強い選手を多く担当した審判の平均が高い」だけになります。

守っていること（公開する場合の必須条件）:

- **母数100演技未満の審判は傾向値を出しません**（「データ不足」と表示）
- 甘い・辛いの判定は**平均パネル差 ±0.10** で付けます
- **審判ランキングは作りません。** 並び順は母数の多い順で、良し悪しの順ではありません
- 各審判に **n・大会数・シーズン数・カテゴリ**を必ず併記します
- 画面に**「観測された採点差であり、審判の能力評価ではありません」**と明記しています
- **審判名がある大会は30大会中15大会だけ**です。無い大会を画面に一覧で出し、
  「データが無い」を「問題が無い」と読み違えさせないようにしています

母集団に加えて**大会・区分・男女・ラウンド**でも絞り込めます。今どの条件で見ているかは常時表示します。
絞り込みをかけたときだけ、`summary/judge_diff_rows.json`（1行＝1審判×1演技のパネル差）から
平均を取り直します。組み合わせが多すぎて事前に全通り計算できないためで、19,000行なので数ミリ秒で終わります。

| 条件 | 内容 | n≥100 の審判 |
|---|---|---|
| 予選通過者・完遂のみ（既定） | 予選の次のラウンド（予選2・準決勝・決勝など）に進んだ選手の、10技完遂の演技 | 45名 |
| 完遂演技のみ | 10技完遂の演技すべて | 50名 |
| すべての演技 | 中断も含む | 77名 |

## 6. 検索エンジンには載せていません

`robots.txt` と各HTMLの `<meta name="robots" content="noindex, nofollow">` で、
検索エンジンのインデックスを止めています。

元データ（各大会のリザルト）は協会・大会運営が公開していますが、その多くはPDFで、
氏名で検索して辿り着くものではありません。このサイトはHTMLなので、そのままだと
**1,600名超の選手名と169名の審判名が Google で検索できる状態**になります。
これは元データには無かった性質の変化なので、止めています。

**URLを知っていれば誰でも見られる状態は変わりません**（リポジトリもPagesも公開設定です）。
iPhoneからの閲覧にも影響しません。検索結果に出なくなるだけです。

## 8. ファイル構成

```
index.html      … リザルト（入口は検索。初期表示は「最近の大会」）
meet.html       … 大会ページ（区分×ラウンドを選ぶと公式PDFと同じ並びの結果表）
athlete.html    … 選手ページ
judges.html     … ジャッジ分析
about.html      … データについて（注記の第3層。出典・欠測・分析の限界）
css/style.css
js/             … 素のES modules。ビルドもnpmも使いません
tools/          … 生データの取得（sporttech・大阪府）。既存の原本には書き込まず、新しいフォルダを足すだけ
                  verify_published.py … 公開データが原本と一致しているかを、ETLとは別の読み方で確かめる
etl/            … Python（標準ライブラリのみ）。生データ→data/*.json
  build.py               ETL本体（--accept-counts で件数の基準を更新）
  acceptance.py          受け入れ基準の自動確認
  regress_sporttech.py   検証済みCSVとの突き合わせ
  athlete_overrides.json 同姓同名の手動指定
  judge_overrides.json   審判の表記ゆれの手動統合
  expected_counts.json   大会ごとの件数の基準（手で編集しないでください）
  known_exceptions.json  検算で説明のつかない演技を理由つきで登録（検査は緩めない）
data/           … ETLの出力（このフォルダは手で編集しないでください）
docs/           … 検証レポート・実装メモ
```

**なぜフレームワークもビルドも使わないか**：npm も node_modules も無いので、
1年後に触っても壊れません。GitHub Pages は push するだけで公開されます。

### 画面の作り

- **入口は検索**です。一覧を見せてから探させるのではなく、知りたい人・大会へ最短で到達させ、
  必要なときだけ詳細を開きます。初期表示は「最近の大会」で、いきなり全件の表は出しません
- **検索・絞り込み・ソートは常に全件が対象**で、表示だけを50件ずつページングします。
  以前は先頭3000件しか描画しておらず、3,001件目以降に到達できませんでした
  （ソート自体は全件で効いていましたが、欠測を含む行は末尾に送られるため事実上見えませんでした）
- **注記は3層**です。各画面には要点1行、クリックで内訳、詳しくは「データについて」ページ。
  注記を消したわけではなく、毎回全文を通過させるのをやめただけです
- **狭い画面（700px以下）ではカード表示**に切り替えます。表の横スクロールは最終手段です
- **大会ページは公式リザルトと同じ並び**です（Rank / Name / S1〜S10 / Lnd / Exe / Diff / ToF / HD / Pen / Score）。
  予選は1選手2行（Q1・Q2）で、順位と予選合計が2行にまたがります。紙のリザルトを見慣れた人が
  同じ順序で目を走らせられるようにするためです。中身が全部空の列は出しません
  （大阪府には順位も所属も無く、決勝は合計・D・Tもありません）。
  **S値の意味はソースで違います**（西日本＝技ごとの減点、sporttech・大阪府＝中央2審判の減点の和）。
  同じ見た目の表なので、必ず注記を出しています

### データの読み込み方

- **画面ごとに要る分だけ読みます。** 2015年以降を取り込んで個人演技が約4万6千件になったため
  - 入口（リザルト）… 起動時は大会一覧と選手の検索用データだけ。演技の全件（年単位のファイル）は
    検索・絞り込み・「すべての記録」を使ったときに初めて読む
  - 大会ページ … `meets/<大会ID>.json`（その大会の演技だけ）
  - 選手ページ … `by_athlete/<束>.json`（選手IDを128の束に分けたうちの1つ。
    束の決め方は `etl/build.py` の `athlete_shard()` と `js/data.js` の `athleteShard()` で同じ計算）
  - 技別減点と審判別Eは**大会単位**（`details/`）で、演技詳細を開いたときだけ
- `manifest.json` の `dataVersion` をクエリに付けて読みます
  （`performances/2026.json?v=2026-08-14-01`）。付けないと、更新したのにブラウザが
  古いJSONを使い続けて「反映されない」事故が起きます

## 9. Phase 2 のための器

`data/judges.json` と `data/panels.json` は Phase 1 で用意済みです。

- sporttech の**15大会**は審判の氏名・所属・パネル配置が入っています（118名）
- 大阪府・西日本・残りの大会は空です
- ETLは「panels.json にエントリがあれば審判名を紐付け、無ければ審判不明として扱う」
  分岐を最初から持っています

**制約**：審判名がある大会でも、`JudgesPanelID = -1` のステージがあります
（例：2026-07-24 全日本ジュニアの決勝）。この場合、誰が採点したかは特定できません。
演技詳細では「大会に審判名が無い」のか「このラウンドのパネル配置だけ記録が無い」のかを
区別して表示しています。

## 10. 生データは書き換えません

`<作業フォルダ>\トランポリンルール\大会リザルト\` 配下は、ETLは**読むだけ**です。一切書き込みません。
新しい原本を足すのは `tools/` の取得スクリプトだけで、**既存のファイル・フォルダには書き込みません**
（あれば飛ばす）。
